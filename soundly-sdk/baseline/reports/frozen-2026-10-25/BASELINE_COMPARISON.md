# 旧 SDK 与当前 SDK 基线对照

## 测量条件

- 旧 SDK：Git `HEAD`，`5f3b8cf75522ef925a0f9195d7e55101f0fbd908`。
- 当前 SDK：同一提交上的本地 SDK 2.0 工作树。
- 对照设备：`Pixel_8_Pro_API_33` Android 模拟器，API 33，RAM 3072 MB。
- 输入：`fixtures-manifest.json` 中完全相同的 6 个 SHA-256 固定样本。
- 处理预设：`RAW`。
- 耗时：不包含 fixture 解压，只统计 SDK 处理调用。
- 内存：每 20 ms 采样一次进程 PSS；下表“峰值”是绝对峰值，“增量”是峰值减初始值。

30 个单元测试和 24 个真机测试仍在 OPPO PHY110 / Android API 36 上冻结。本表改用隔离模拟器，是为了避免真机在 30 分钟 OOM 后的媒体服务休眠和高 Swap 污染旧/新版本对照数据。

|---|---|---|---:|---:|---:|---:|---:|---:|---|

## 输出结论

1. 四个成功样本的输出 WAV 大小和 SHA-256 在旧版与当前版之间完全一致；当前外围改造没有改变这些 RAW 样本的字节输出。
2. 损坏文件在两版中都以 `IOException: Failed to instantiate extractor.` 结束，没有错误输出文件。
3. 30 分钟样本在两版中都因整段 PCM 驻留内存而 OOM。当前版峰值 PSS 为 355,640 KB，旧版为 350,210 KB；工作项 14 明确仍未完成。
4. 5 分钟样本当前版峰值比旧版高 10,649 KB，耗时差 23 ms。单次结果只能作为冻结基线，不应当解释成统计学性能回归；后续工作项 14/20 应增加多轮、冷启动和真机矩阵。
5. 当前版已修复的“RAW 不应经过 Limiter”在本组输入上没有改变最终字节结果，说明这些样本未触发旧 Limiter 的有效削波区间；对应行为仍由 `RawPipelineTest` 单元测试固定。

机器可读的全部原始字段、错误类型、输出 SHA-256 和逐样本初始/峰值 PSS 位于 `sdk-comparison.json`。

## 真机补充观察

首次在 OPPO PHY110 / Android API 36 执行当前版压力探针时：5 分钟样本成功，30 分钟样本同样触发 OOM。之后设备出现高 Swap，旧版媒体解码任务进入休眠，因此未把受污染的真机耗时混入上表。功能基线的 24 个真机测试是在压力探针之前完成，结果不受此问题影响。
