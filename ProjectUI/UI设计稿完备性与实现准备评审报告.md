# Soundly UI 设计稿完备性与实现准备评审报告

评审日期：2026-11-14。范围：`ProjectUI/APP` 全部设计图、M0 功能基线、M6 集成验收记录、当前 App 与相关 SDK 源码。

## 1. 结论

**F01～F38 的页面编号已经齐全，可以开始公共组件、页面骨架及已明确主路径的高保真迁移；但还不能把现有图片当作无需补充说明即可完整实现的冻结规格。**

当前目录有 **39 张 PNG，覆盖全部 38 个 F 编号**，其中 F03 分为 A/B。此前缺少的 F04、F05、F06 已补齐，不再属于缺稿。真正欠缺的是过程/失败状态、危险操作确认、选择控件展开态，以及跨页行为和业务能力映射。

建议按模块推进：先确定本报告 P0 项，再实现录音、增强、导出等对应模块；通用布局与已有稳定页面可以同步开展。无需重做整套设计，也无需为每个局部状态新增完整页面。

本报告为静态设计及源码评审，未运行 App、未做真机验收，无法仅凭截图判断实际触控尺寸、文字对比度数值或运行稳定性。M6 文档仍标记“代码集成完成；真机验收待执行”。

## 4. 现有设计稿需要调整或明确的事项

### A01｜P0：统一 F24/F25/F33 的输出格式、文件名和位置规则

**现状：** F24 的说明为“当前增强版本的音频格式”，F33 允许设置默认输出格式，同时提示“实际导出格式需与所选音频版本一致”。这会让默认格式设置的效果不清楚。

**代码事实：** SDK `exportUsingDefaults()` 读取 `settings.outputFormat`。相同格式可以直接复制，M4A/AAC/MP3 可解码导出 PCM16 WAV，其他转换会明确拒绝。`prepareShare()` 则按所选版本原格式复制，不按默认导出格式转码。当前 App Gateway 固定 Downloads，尚未传入用户编辑后的导出名称。

**建议：** F24 明确显示“当前操作版本＋本次导出格式”；默认使用 F33 偏好，不支持时提示原因并给原格式/WAV 可用选项。删改“必须一致”的绝对表述。分享显示“按当前版本原格式分享”，不要暗示导出设置必然作用于分享。若首版固定目录，保存位置画为只读并显示实际 `Download/Soundly`；若允许修改，补系统保存位置选择衔接并扩展 App Gateway。F25 使用真实结果名称/格式/路径，重名自动编号后不能继续显示原计划名。

### A02｜P0：F18 四种模式与 SDK 预设建立映射

**现状：** UI 为“自动增强、清晰人声、降低噪声、自然平衡”；App 当前提供 AI、DEFAULT、SPEECH_FOCUS、VOICE_STABLE、NATURAL_SMOOTH 五项。SDK 还有场景预设。UI 显示“自动”不能只由名称猜测为 AI/RNNoise。

**建议：** 交付“UI 名称 → PresetOption → 默认值 → 推荐来源 → 失败处理”表。自动模式究竟是固定预设还是分析后推荐必须确定；目前公开 `EnhancementResult` 不含推荐理由/效果摘要，不应把枚举选择当成自动效果诊断。产品可只展示四个入口，但需明确是 SDK 能力的子集和组合策略，不能直接删除既有业务契约。

### A03｜P0：F03-B/F07/F32 的场景与单次设置作用域

**现状：** 首页场景、准备页场景和默认场景三处可选，没有说明相互覆盖顺序。F07 画了可调整场景和音质；当前 `PrepareRecordingFragment` 只按全局默认配置启动，尚未实现单次覆盖。UI“语音备忘”也没有同名 `RecordingScene` 枚举。

**建议：** 规定优先级“本次准备页覆盖 > 首页本次选择 > 全局默认”；首页选择是否持久化必须统一。为“语音备忘”明确 OTHER/PODCAST 等哪项实际映射，或新增能力走单独契约调整。F07 的“手机麦克风”建议维持只读；若需外接/蓝牙音源选择，则另补能力与状态，不能由这一行文字推断已经支持。

### A04｜P0：F10 改为 Android 通知能力范围内的设计

**现状：** F10 包含定制通知波形、场景、音质和精细布局。现有 SDK 使用标准 `NotificationCompat` 通知，提供时长、暂停/继续、停止动作，没有该波形布局或公开通知样式配置。

**建议：** 首版采用系统标准通知，以通知内容与动作规范交付，不要求复制系统快捷设置栏。补暂停后的“继续”、锁屏内容和点击返回活动录音的规则；Android 13+ 通知授权独立于麦克风处理。若必须实现稿中通知，需先扩展 SDK 公开配置能力，再处理系统版本限制。通知被拒绝不应直接等同于麦克风不可用。

### A05｜P0：F22/F23 效果文案改成有数据依据的表达

**现状：** 两张图固定勾选“整体音量更加稳定、人声更加清晰、持续背景噪声已降低”。SDK 公开结果提供版本、时长、preset、taskId，没有逐项效果检测数据。

**建议：** 可改为“本次模式：自动增强；处理方向：平衡音量、优化人声与背景噪声”，并引导实际试听。若要保留“已降低”等结论，必须先有真实检测依据及条件显示规则。下方“原始录音 · M4A”应标为“来源”，另明确当前选中版本的格式，避免 F22 的增强试听与原始格式混淆。

### A06｜P0：F11 与既有功能基线的动作数量冲突

**现状：** 视觉稿只有“返回录音、放弃录音”，M0 和当前代码另有“保存”动作；现有稿背景为暂停状态，调用时是否自动暂停未定义。

**建议：** 若保持 M0 冻结契约，补“结束并保存”操作及三按钮布局，并规定退出前是否暂停、取消后回到什么状态。若选择两按钮方案，应明确保存仍可在何处完成，并正式同步基线与验收，不把删动作当纯换皮。对系统返回、顶部返回和应用切后台分别定义，切后台不应误触放弃确认。

### A07｜P1：F15 原音编辑/导出的可发现性

F15 主体强调增强，首尾裁剪和直接导出入口不可见，功能基线要求这些操作。建议补更多菜单展开稿，并在“不增强”后的 F28 保证明确入口，或提供轻量次级动作。F30 已有裁剪与保存分享入口，两种预览的动作命名和位置尽量统一。

### A08｜P1：F08/F09/F11/F38 控件与时间格式统一

暂停稿中心按钮为红色麦克风，F11 背景却为紫色播放符号，底部完成图标也不一致。建议统一继续录音、完成、放弃的形状/颜色/术语。录音页示例用 HH:MM:SS，预览多用 MM:SS，录音库有一小时示例；明确小于/大于一小时的统一显示规则。暂停时标记按钮是否禁用也要写入规则，而非仅由灰色猜测。

### A09｜P1：F12 不要用麦克风占用文案覆盖所有中断

SDK 区分焦点丢失、来电、输入设备断开、麦克风不可用、空间不足和未知原因。F12 当前只画麦克风不可用，建议保留布局、提供文案变体，并按原因决定恢复/保存入口。F13 的 16 MB 门槛与 SDK 的 16 MiB 阈值需采用一致单位和比较规则，由真实容量驱动，不使用固定示例值。F14“已找到录音内容”应区分发现残留与恢复验证成功，避免恢复前即保证成功。

### A10｜P1：F27 的筛选与非空库导入入口

“已增强、原始录音、已导入”并非互斥类别：导入项目也可增强。明确每个筛选是来源还是“拥有某类版本”，允许同一项目出现在不同筛选结果。F27 只有新建录音悬浮按钮，非空库导入需要返回首页；建议新增明确导入入口或“＋”动作菜单，至少与已有空库导入路径保持可发现性。

### A11｜P1：F28 展示真实版本谱系，明确比较对象

裁剪会产生新版本，但稿中只有原音和增强样例。补来源版本、模式、创建时间或编号，避免多个“自动增强”无法区分。对裁剪版本做增强时，AB 的“原始”应指本次输入版本，建议改为“处理前/增强后”，或明确仍比较项目最初原音；不同长度版本不能直接假定时间轴一一对应。导出、裁剪、增强应操作当前选择版本。

### A12｜P1：F32/F33 控件选项与代码能力保持一致

SDK 录音格式当前只允许 M4A/AAC，不能把 MP3/WAV/UNKNOWN 枚举全显示为可录制选项；当前 App 确实直接绑定全部格式枚举，需在迁移时修正。输出格式也不能承诺任意转码。F33 的“数字编号”实际命名策略为 epoch 毫秒时间戳，不是 001 递增，建议改名或明确样例。当前代码另有“后台录音”设置，稿中未画；确定保留并补控件，或明确产品统一策略及对应基线变更。

### A13｜P1：F34/F35 和 F36 的小文案与状态衔接

清缓存成功应显示“已清理 X”或“缓存已清理”，不沿用当前代码通用“设置已保存”。清空本地数据是否重置引导、主题等 App 偏好要另定，不能仅靠 SDK 删除名称推断。F36 设计有反馈输入框和诊断开关，但当前代码是两个邮件入口、没有把用户输入接入邮件正文的逻辑；迁移时补齐。诊断开关默认关闭并写入草稿，发信仍由用户在邮件应用确认。

## 5. 跨页面交付还缺什么

目录目前主要是 PNG，没有在 ProjectUI 中发现独立组件规范、颜色/字号表、矢量资产目录或交互标注文件。**这不证明设计源文件不存在，但当前仓库交付不足以无歧义地还原。** 建议补一个轻量交付包：

| 交付项 | 必要内容 | 优先级 |
|---|---|---|
| 设计变量 | 主色/语义色、文字层级、背景、间距、圆角、描边、阴影、渐变参数，单位以 dp/sp 表达 | P1；公共组件精修前 |
| 可复用组件 | 顶部栏、底部 Tab、主次/危险按钮、输入框、选择弹层、确认框、状态提示、播放器、项目行、版本行 | P1 |
| 资源 | Logo、麦克风/文件/标记等图标、插画的 SVG/VectorDrawable 或适合密度的透明资源；说明可用平台图标替代的范围 | P1 |
| 波形规则 | 实时滚动/静态抽样、播放游标、标记密集时避让、裁剪把手与选区交互；不硬编码示例波形 | P1 |
| 适配与可访问性 | 小屏和大字体重排、长名称省略/换行、键盘避让、系统栏/insets、可滚动区域、触控目标、TalkBack 标签 | P1 |

## 7. 建议的实现顺序与开工门槛

1. **先冻结会改变业务行为的规格：** A01～A06，以及 S01～S06 的基本交互；交付一张模式映射表、一张导出能力表、一张导航/状态表即可，不必等全部视觉细节完成。
2. **并行落实公共组件：** 色彩、字阶、按钮、确认框、输入/错误提示、播放器、项目/版本行，确定深色范围与 insets 策略。
3. **录音主闭环：** F01～F17、F38，包括权限拒绝、录音中断、空间不足、保存失败和恢复，完成后做设备验证。
4. **增强与导出闭环：** F18～F25、F30，先跑通真实数据、模式、版本、进度与错误，再核对视觉；同时验证直接导出原音和分享原格式。
5. **项目与设置闭环：** F26～F37，覆盖裁剪版本、无搜索结果、清空数据和反馈降级。F37 按当前介绍页实现，不接购买。
6. **按状态验收：** 检查成功、等待、失败、取消、返回、多次点击、小屏/大字体、深色及前后台；不要只逐张截图验收。

可以先做：F02 引导、F03/F04 首页基础布局、F26/F27 列表组件、F31 设置入口、F35 隐私内容、F37 介绍页及通用视觉资源。

对应规则未冻结前避免定死：F07 单次配置、F10 定制通知、F11 动作、F18 模式名称、F22/F23 效果摘要、F24/F33 导出格式。
