# 导入主流程 I0 契约

日期：2026-11-16。本文冻结 I1～I6 的实施边界；其中“当前”描述的是 I0 时的基线。I1、I2 的实际交付与验证分别见 [I1 交付记录](IMPORT_FLOW_I1_PROGRESS.md)和 [I2 交付记录](IMPORT_FLOW_I2_DELIVERY.md)。

## 1. 对象、流程与版本

| 节点 | 输入／状态 | 下一步及约束 |
|---|---|---|
| 首页 F03-A/F04、F06、库 F26/F27 | 当前入口、无活动导入 | 打开系统文件选择器；不申请麦克风权限。F06 权限控制器只负责返回导入意图，统一导入协调器执行。 |
| 系统选择器 | `OpenDocument`，单文件 `audio/*`；provider 返回 URI 或取消 | 取消回实际入口，不创建项目、不报错。MIME 筛选仅为提示，仍需 SDK 检查内容。 |
| 导入 | 单次操作 ID、来源 URI、可用授权、进行中／成功／失败／结果待核验 | 不确定进度；只在真实项目落库后进入 F30。处理中禁止再次发起和离开导致重复；配置变更继续观察同一任务。没有能力前不提供取消按钮。 |
| F30 | 明确 `projectId + selectedVariantId`；来源为导入项目 | 初次显示导入原始版本；裁剪成功切换到返回的新版本。播放、增强、导出都使用当前版本；缺失时报错，不回退到其他版本。 |
| F16 / F17 | 当前项目及选中版本 | 重命名只更改项目标题；F17 取消保留原选择，成功以结果 ID 更新实际调用页，然后返回调用页，不新增重复预览栈。 |
| F18～F23 | 项目 ID、本次输入版本 ID、增强任务 ID、增强结果版本 ID | “处理前”是本次输入，可能是裁剪版；取消或失败回实际来源及原选中版本。AB 位置限于双方可用时长。 |
| F24/F25、F27 | 用户当前选择的版本 ID／真实导出结果 | 按 H7 能力和恢复规则导出；分享为所选源版本。返回库，系统返回不再触发导入、裁剪、增强或导出。 |

选区、导入成功页、错误和确认等状态以 ViewModel 状态表示；导航、启动系统 UI 等为需确认消费的一次性事件。F30 与 F17 接入固定顶部栏和日夜主题。返回来源采用 Navigation 返回栈及显式结果交付，不以录音来源或固定 destination 推断。

## 2. 导入提交与恢复：I1 必须实现

当前 SDK `DefaultAudioImporter` 内部生成随机项目 ID，`AudioImportRequest` 没有调用方操作 ID；接口无进度/取消查询。`copyAtomically` 有暂存文件和移动，但文件系统与 Room 不是一个事务；当前通用异常分支也会捕获协程取消。不能把现状描述为支持进程恢复或幂等。

采用以下方案，I1 实现前不能宣称完成可靠导入：

1. App 在启动导入前生成唯一随机操作 ID，**同步持久化**操作 ID 和阶段后才调用 SDK。SDK 新增兼容旧调用的显式导入请求/结果查询能力，使用此 ID 关联唯一项目 ID；旧 API 保持可用。使用数据库唯一约束及单操作互斥，重复提交必须返回同一结果或明确的进行中状态，不能覆盖既有项目。
2. SDK 管理每个操作专属暂存文件与目标目录；记录复制、文件就绪、数据库提交和终态。成功的唯一判断是查询到与该操作 ID 一致的完整项目、原始版本及可读文件。数据库提交与文件移动之间的中断必须能通过持久化记录判别；数据库查询失败或结果不确定时禁止删除可能已提交的文件。
3. 恢复时先按操作 ID 读取提交状态并核验项目及文件；成功则恢复 F30，明确未提交且无活动任务时清理该操作的残留，再提示用户重新选择或明确重试；未知或查询失败显示待核验状态，不能按文件名/时间猜测，也不自动创建新项目。清理只允许作用于该操作已确认未提交的私有文件，不扫除其他项目或用户源文件。
4. 后台运行由流程作用域持有而非页面 `viewLifecycleOwner`；重建只重新观察。进程终止后不假定协程仍在运行。`CancellationException` 要透传并按提交阶段安全清理；提交可能已完成时先核验，不能一律删除目录。大文件复制需在 IO 线程并检查可用空间及未知大小时的写入失败。
5. 使用系统授予的 URI 读取权限完成复制；是否取得可持久权限取决于 provider 和实际授权结果。不能假定所有 provider 支持跨进程访问。权限失效／云端不可达时提示重新选择；无条件重复导入不可用。复制完成后预览只依赖本地副本。

首版不提供假的百分比、继续后台运行或可取消承诺。若 I1 无法交付上述身份、提交与核验能力，应如实标记未完成，不绕过门禁。

## 3. 格式、波形与元数据

| 能力 | 规则 |
|---|---|
| 导入 | 当前识别 WAV、M4A、AAC、MP3；实际可导入、播放、解码取决于内容、编码及设备能力。损坏、无音轨、受保护、权限与空间不足分别映射为可理解错误，不依赖扩展名承诺可用。 |
| 裁剪 | 当前 SDK 仅 WAV、M4A；通过 `TrimCapabilities.supports` 作为权威查询，AAC/MP3 保留可用的播放、增强和导出入口，裁剪入口说明暂不支持，不静默转码。扩展格式必须先扩 SDK 并测试。 |
| 波形 | 当前录音波形接口仅读取已存储数据，导入器未生成；I2 在 SDK 增加基于本地版本的真实生成与缓存，单版本防重复、IO 执行、有界采样、失败可重试。生成失败不影响播放或导出，不使用示例波形伪装真实数据。 |
| 元数据 | 原始显示名与可修改项目名分开。现有模型未持久化显示名，且 reader 可能用 URI 尾段或默认名回退；I1/I2 需新增可空、标明可信来源的显示名并做 Room 迁移。旧记录、provider 未提供名称时显示不可用；不把 URI 路径或默认项目名当原始文件名。 |
| 导出 | 源 WAV 可导出 WAV；M4A/AAC/MP3 可选择源格式或 WAV，实际解码仍可能失败。F24 按真实版本能力筛选；不把导出格式选择解释为分享格式。 |

## 4. 裁剪范围、试听与结果

以当前版本的真实时长为准，合法范围为 `0 ≤ startMs < endMs ≤ durationMs`，时间单位毫秒。产品层不额外强制最小时长；最小可表示的非零范围为 1 ms，**合法范围不保证实际存在完整采样帧或能够生成有效文件**。SDK 仍需验证实际文件及边界，失败时保留选区并说明。时间计算不得溢出；长文件提供可访问的细调/明确时间操作，而不只依赖拖动像素。

试听只播放选区：从起点播放，到终点停止或暂停并回到可再次试听的状态；切换选区、离开页面、其他页面取得播放器时释放或暂停，遵循音频焦点。试听不写文件。裁剪中防重复，失败可重试且保留来源和选区；完成后使用 SDK 返回的实际版本 ID 和实际时长。

WAV 以采样边界裁剪；M4A 使用 `MediaExtractor` 选取完整音频帧并重新封装，实际边界可能与请求不同。UI 不承诺逐毫秒精度；需要在 I3 使用已知音频实测首尾内容和时长，并以实际元数据展示结果。标记使用 SDK 返回的相对时间，不假定与项目原始时间直接相等。

## 5. SDK 和 App 增量清单

| 阶段 | 必需增量 | 兼容约束 |
|---|---|---|
| I0 已落地 | SDK `TrimCapabilities` 暴露支持格式与范围校验；SDK 裁剪器使用同一规则 | 保持旧 `previewTrim` / `applyTrim` 接口及错误语义；范围合法不代表处理一定成功。 |
| I1 | SDK 导入操作身份、唯一性、持久记录与核验、取消和文件清理审计；App 导入协调器、状态与系统选择器；来源名称可信度及数据库迁移 | 保留原 Gateway 和 SDK 调用方；绝不替换现有用户项目或破坏其他模块数据。 |
| I2 | SDK 本地版本波形生成/缓存；F30 共享播放器、真实元数据与来源版本 | 未获得显示名的旧数据允许为空；波形不可用可播放。 |
| I3 | Gateway 附加完整 `TrimPreview` 路径，同时保留旧时长接口；F17 状态、选区控件和结果返回 | SDK 仍为裁剪唯一实现；保留原录音流程接口。 |
| I4/I5 | 增强返回上下文、AB 来源文案和 F24 裁剪版本标签；最小项目版本展示 | 校验原音、裁剪、增强各自身份；复用 H6/H7，不改分享语义。 |

## 6. 验收与缺稿

I0 的自动测试覆盖支持格式与范围边界；I1 必须补复制前、文件移动前后、数据库提交前后、结果记录前后故障注入以及并发重试和授权失效测试。I2～I5 按里程碑文档验证真实文件、版本链与返回栈。I6 必须包含系统文件选择器、云 provider、进程终止、API 26/33/35+ 和真机音频及浅深色/大字体。模拟器、构建或 Activity 重建不替代真机和进程终止验收。

设计稿缺少导入中/失败、波形缺失、F17 不合法范围及应用中/失败、多版本来源等状态；后续使用 Material 公共状态并记录视觉决策，不虚构设计稿编号。F30 源名称缺失显示“来源文件名不可用”，导入/裁剪错误应提供实际可行的重试或返回动作。
